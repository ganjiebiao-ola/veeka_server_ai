# 问答补齐循环与完成度判定(qa loop)

[#115](https://github.com/olaola-projects/ai-native-issues/issues/115) 交付物:Phase 3 的循环
流程、完成度判定与退出条件。输入 = Phase 2 产出的 00 缺口报告 + 四份 spec;目标对齐父票
非目标:**「够驱动生成即可」,不追求 Spec 完美化** —— 循环的目的是尽快让 Spec 可交付下游
生成,不是清零所有 CL。

> 借鉴声明:限量提问、按影响排序、回答即时写回的循环思想借自 spec-kit `/speckit.clarify`
> (只借思想,不引入其命令链);复用边界见 `upstream-reuse.md`。

## 默认阈值(owner 可调,调整记录在 00 报告元信息)

| 参数 | 默认值 | 说明 |
|---|---|---|
| 每轮问题数上限 | 5 | 降低 owner 单轮负担;按影响排序,截断的留到下一轮 |
| 轮次上限 | 3 | 达上限触发强制退出 |
| D4 残留 CL 上限 | 5 | P2/P3 允许带风险残留的未决 CL 条数 |
| 问答 SLA | 24h/轮 | 与需求 owner 确认后记入报告元信息;未确认前留待定 |

## 每轮流程(R1、R2、…)

开轮前检查:存量 00 报告若早于现行模板(§5/§6 仍是占位注释),先按现行模板补齐骨架再开轮。

1. **选题**:从 00 报告未决项中选**至多 5 问**。排序键:① 阻断 P1 用户故事的 FR/AC;
   ② 04 硬性红线与目标引擎选型;③ §3 不自洽裁决题;④ coverage 关键章节的整章缺失;
   ⑤ 其余。同级按 CL 编号升序;一问共挂多条 GAP 的(见 gap-rules.md)只问一次。
   **门禁保底名额**:若存在 D1 阻断项(引擎定版/红线空置)或 D3 阻断项(§3 open 裁决题),
   至少保留 1 个名额给其中最高优先者 —— 否则 ① 级挤满 5 问时,门禁阻断项会被轮次上限
   拖死。选题候选、排序依据与被截断项记入 §5「选题记录」。
2. **出问卷**:每问必带 —— CL 编号、问题本体、影响面(阻断哪条 FR / 哪章),可枚举时给
   2–3 个选项 + 其他(降低回答成本)。问卷写入 00 报告 §5「R<n>」,发给需求 owner。
3. **吸收回答**:逐条处置,三种情形:
   - 回答明确 → 写回对应 spec 章节:替换 [NEEDS CLARIFICATION(CL-###)] 为实答内容并注
     来源「owner R<n>」;
   - 回答仍含糊 → CL 保留**原编号**、在下一轮细化问题(不换号,问答历史留在 §5);
     spec 侧标记文本**同步更新**为细化后的问题(部分答复写入正文),避免残留过时问法;
   - 回答引出新缺口 → 按 gap-rules.md 判类记新 GAP 行,需要 owner 供事实的开新 CL(全局续号)。
4. **更新报告**:§2/§3 对应行标 `resolved(R<n>)`(行不删除,保留审计轨迹);重算 §1
   (类别 × 文件矩阵 = **累计发现**含 resolved;未决 CL 计数单独列,按去重编号数对账);
   §4 按轮追加本轮写回摘要(落点非 VCS 时这是唯一审计轨迹);§5 记本轮小结 ——
   **resolved 数与「零新增 resolved」判定一律按去重 CL 计**(一个 CL 关多条 GAP 只算 1)。
5. **判定**:按下方 D1–D4 逐维判定并写入 §6;通过 → 收敛(见退出条件),否则回到 1。

## 完成度判定:「够驱动生成」的操作化(D1–D4)

- **D1 硬门禁**:P1 用户故事及其 FR/AC **零未决 CL**;04 §1 目标引擎已单选定版(或经裁决
  记「不适用」);04 §7 硬性红线逐条有**适用性结论**(适用/不适用均可,不允许空置;红线
  门禁的实际执行在生成/合并期,此处不要求门禁已跑)。
- **D2 覆盖门禁**:四份 spec 的「完成度总检查表」逐章满足:要么写实且如实勾选,要么显式
  「不适用 + 原因」**定案**(悬置在某个未决 CL 上的「暂不适用」不算定案)—— 二者皆无即 FAIL。
- **D3 一致性门禁**:§3 不自洽对照**全部 resolved**。不自洽是下游生成的毒药 —— 这是唯一
  要求清零的类别。
- **D4 残留额度**:P2/P3 的未决 CL 允许残留,但每条必须标「残留风险 + 默认处理」(如
  「按 MAY 跳过」「生成时留 TODO 不实现」);残留数 ≤ 上限(默认 5)。P1/P2/P3 分级以
  00 报告 §2 的优先级列为准(D 判定不靠散文重推)。

判定与单文件 checklist 的关系:各文件的「完成度总检查表」是单文件自评输入,D1–D4 是
spec-set 级的合成判定;判定不修改模板本身。

## 退出条件

- **正常收敛**:D1–D3 全 PASS 且 D4 达标 → 报告 §6 给出状态建议「评审中 → 够驱动生成」,
  **owner 确认**后生效(skill 逐维判定、owner 终审;确认记录写入 §6)。
- **强制退出**(满足其一):(a) 连续 2 轮零新增 resolved(按去重 CL 计);(b) 达轮次上限;
  (c) owner 显式叫停。→ 未决 CL 逐条转「已知风险」清单入 §6(每条带残留风险与默认处理),状态停在
  「评审中」,是否带风险进下游生成由 owner 拍板。
- 退出条件里**不存在**「所有 CL 关闭」—— 那是 Spec 完美化,父票明确非目标。

## 状态推进

草稿(Phase 1 产出)→ 评审中(Phase 2 报告产出即置)→ 够驱动生成(D1–D4 通过 + owner
确认)。三态字面已在 01–04 模板元信息行,Phase 3 不改模板、只推进值。
