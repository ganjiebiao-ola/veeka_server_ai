每周，一条完整的协作流程

建议流程
1

采集用量与证据

平台导出、本机记录、账单，以及任务与交付链接。

2

个人确认后提交

AI 起草工作小结，个人确认成果、归属和分享内容。

3

系统校验并汇总

统一口径、去重、识别缺失，合并多人协作成果。

4

Lead 审阅与决策

确认团队摘要，生成 HTML，支持资源调整与经验复用。

程序计算

用量、费用、分摊、去重和图表由确定性程序生成。

AI 起草

根据证据整理工作、经验和风险，不补造数字。

人确认

成员确认自己的成果，负责人确认团队结论。

数据从哪里来

每个指标保留来源、时间范围与确认状态。

用量

统一 API 平台导出或只读接口；Claude / Codex 本机 usage 日志。相同使用记录择一计入。

实际费用

供应商账单、订阅台账和付款凭证。API、Seat、GPU 和共享资源分别记录。

工作成果

任务、PR、Git 提交、CI 结果、文档或其他业务交付物，按任务关联。

价值与经验

个人确认效率或质量改善、可复用方法、失败结论和工具问题。

三种金额，分别展示

避免把 Token 折算金额当作报销金额。

实际费用

账单确认的费用，进入核算与报销。

估算费用

Token × 对应模型价格；标明价格版本与缺失模型。

分摊费用

按服务周期、项目用途或确认比例分配实际费用。

例子，仅说明口径
订阅实付 $200，API 等价用量估算 $800。两者并列展示，不相加；报销按实际账单处理。

HTML 用来阅读，结构化记录用来汇总
记录部分必需内容谁负责确认
身份与周期成员、团队、业务/职能、报告周、时区、提交版本成员 / 团队配置
用量与费用来源、工具/模型、Token 分类、金额、币种、费用性质、覆盖时间采集程序 / 账单负责人
工作与价值任务、AI 参与方式、交付物、状态、证据链接、改善说明成员
经验与需求可复用方法、失败探索、工具问题、下一步资源需求成员 / team lead
质量与归属缺失来源、未定价模型、共享费用、分摊比例、确认状态程序检查 / 归属负责人

从第一版开始

复用个人采集器，接收平台 CSV / Excel 和个人 JSON；用统一提交表补齐成果，汇总后套用固定 HTML 模板。流程稳定后，再接自动数据同步。

可追溯

每个数字能查到来源，估算与实际账单明确区分。

可复核

跨周按事件时间划分，缓存子项不重复相加，缺失不填零。

可协作

重复提交更新原记录；同一成果去重；共享费用独立归属。

汇总前的六项校验

来源不重复

网关记录与本机日志重叠时择一计入；不同机器重复记录去重。

周期一致

固定团队时区与周一至周日；跨周会话按事件时间计算。

金额可解释

实际、估算、分摊分列；不同币种保留原币及换算依据。

归属守恒

跨团队费用分摊比例合计 100%，共享资源不全算给账号持有人。

缺失可见

未提交、采集失败、缺少账单与实际为零分别展示。

成果有依据

任务与交付物可核验；时间节省、质量改善需证据或个人说明。
